# 7.8 re-scope decision (2026-05-29)

Operator-approved re-scope of roadmap gate 7.8, originally "Removal of `pi-subagents` +
`taskplane`". The literal wording was wrong; 7.8 is split:

## 1. `pi-subagents` + `pi-multiagent` (npm) — DONE + validated
- Already absent from the global `~/.pi/agent/settings.json` `packages` array (removed during the
  Option-C interactive smoke and not re-added).
- Nothing broke: Stellar persona `Agent()` flows load the **openswarm-bundled** pi-subagents
  (`~/.pi/agent/extensions/openswarm/node_modules/pi-subagents/…`), not the npm package; and the
  hb-orchestra fork provides `Agent`/`agent_team` via `-e`.
- Validated by days of normal sessions + the green interactive L6 smoke.
- Backups: `~/.pi/agent/maintenance/pi-7.8-prep/` (current config + a pre-removal rollback copy).
- Rollback if ever needed: `pi install npm:@tintinweb/pi-subagents && pi install npm:pi-multiagent`.

## 2. `taskplane` — DEFERRED to fork v2 (do NOT remove now)
- The fork does not replace taskplane's supervisor/worker/merger orchestration (explicitly v2 in
  `HB_ORCHESTRA_README.md`).
- Live consumers that would break on removal: Stellar personas `supervisor`, `task-worker`,
  `task-reviewer`, `task-merger`; skills `taskplane-integration`, `create-taskplane-task`.
- Decision: keep `taskplane` installed until the fork ships v2 supervisor/worker/merger.

## 3. openswarm-bundled `pi-subagents` — separate track
- `~/.pi/agent/extensions/openswarm` vendors its own `pi-subagents`. Migrating personas off that
  bundle onto the fork's `Agent` is independent of 7.8 and not required for it.

Full cross-workspace consumer map + backup/rollback steps:
`~/.pi/agent/maintenance/pi-7.8-prep/7.8-CONSUMER-MAP-AND-PLAN.md` (machine-local).
